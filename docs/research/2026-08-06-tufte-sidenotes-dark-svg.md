# Tufte 旁注与暗色 SVG 调研

日期：2026-08-06

## 调研范围

本次调研只确定问题、约束和可选方向，不修改页面、同步管线或 vault 内容。

两个问题共享一个目标：正文、补充信息和插图应在读者当前阅读位置协同。两个问题的实现路径和验收条件相互独立，可以分阶段交付。

## 当前实现

### 旁注

- 正文宽度为 680px。宽屏时页面为正文 680px、间隔 72px、侧栏 240px。
- `.sidenote` 已有完整样式。宽屏时它向右浮动到 240px 侧栏；窄屏时它回到正文，显示为带“旁注”标签的块。
- `content-zh/`、`playground/`、页面组件和测试中没有任何旁注内容。
- vault 是正文事实源。同步脚本当前只会把 Obsidian callout 降级为普通引用，不会生成旁注 AST。
- Markdown 管线没有开启原始 HTML，因此不适合要求作者手写 Tufte CSS 的 `label + input + span` 结构。

结论：侧栏不是布局缺失。缺口是“作者如何写旁注”和“同步管线如何保留旁注意义”。

### 暗色 SVG

- 页面通过 `html[data-theme="black"]` 切换颜色变量，并同时设置 `color-scheme: dark`。
- 站点现有 279 个 SVG。249 个包含 `#312f2f` 深色墨线，217 个包含珊瑚强调色，195 个包含浅灰轴线。
- 163 个 SVG 含内部 `<style>`。颜色总数为 359，但主要颜色高度集中，适合归并为少量语义颜色。
- 当前 SVG 以 `<img>` 外链方式加载。页面 CSS 变量不会直接进入 SVG 文档。
- 本地截图确认：暗色正文和 MathJax 正常，`lengths-and-distances.1.svg` 的坐标轴、标签与主要线条仍按浅色绘制，部分内容难以辨认。

结论：问题来自 SVG 内部颜色写死。单独调整 `<img>` 外层样式不能可靠修复图内不同语义颜色。

## 外部依据

### Tufte 旁注

Tufte CSS 将旁注定义为与当前正文紧邻的次要信息。宽屏时旁注进入页边；窄屏时通过开关显示。官方实现区分两类：

- `sidenote`：正文有编号锚点，适合引用和需要精确对应的补充。
- `marginnote`：无编号，适合短解释、小图或不需要逐项对应的补充。

官方说明强调：旁注应承载相关但非必要的信息，不得干扰主论证的推进。来源：[Tufte CSS 官方示例](https://raw.githubusercontent.com/edwardtufte/tufte-css/gh-pages/index.html)。

### 外链 SVG 的主题传播

Media Queries Level 5 规定：以图片方式嵌入的 SVG 在安全动画模式下，其 `prefers-color-scheme` 应反映嵌入节点的已用配色。MDN 也给出 `<img src="...svg">` 内使用 `@media (prefers-color-scheme: dark)` 的示例。

当前页面在黑色主题下已设置 `color-scheme: dark`。本地最小实验确认：同一个外链 SVG 可以根据父页面的 `color-scheme` 切换内部墨线、背景和强调色，无需内联 SVG，也无需复制明暗两份文件。

来源：[MDN `prefers-color-scheme`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-color-scheme)、[Media Queries Level 5](https://www.w3.org/TR/mediaqueries-5/#prefers-color-scheme)。

### 对比度底线

WCAG 2.2 要求必要图形相对相邻颜色达到至少 3:1；图内普通文字应达到至少 4.5:1。细线即使名义达标，抗锯齿也会降低实际辨识度，宜保留额外余量。

来源：[W3C 非文本对比度说明](https://www.w3.org/WAI/WCAG22/understanding/non-text-contrast.html)、[WCAG 2.2](https://www.w3.org/TR/WCAG22/#contrast-minimum)。

## 旁注方案

### 方案 A：Obsidian callout 作为唯一作者语法

作者在 vault 中写专用 callout，例如 `> [!sidenote]`。同步管线将其转换为旁注节点。

优点：作者可在 Obsidian 中直接识别；符合 vault 事实源；不引入原始 HTML；可在同步时做长度和结构校验。

风险：普通 blockquote 与旁注需要在剥离 callout 之前分流；行内锚点与段落级 callout 的对应关系需要明确。

### 方案 B：Markdown 脚注复用

把普通脚注渲染为宽屏旁注，窄屏保留脚注或内联展开。

优点：编号、锚点和可访问性语义成熟；适合来源引用。

风险：当前内容没有脚注约定；脚注通常放在文末，和 vault 写作习惯不完全一致；无编号 margin note 仍需第二套语法。

### 方案 C：自动抽取括号、定义或相关链接

管线自动把某些正文片段移入侧栏。

优点：不增加作者操作。

风险：算法无法稳定判断信息是否“非必要”；会破坏正文自足性；回归范围覆盖全部词条。

不推荐。

### 旁注推荐

采用 Obsidian 原生可读的两种作者语法，并由管线生成语义节点：

1. 编号旁注使用 Markdown 脚注，承载来源或严格对应某个符号与句子的补充。
2. 无编号边注使用专用 callout，承载术语提醒、前置知识、数值核对和常见误读。

现有 vault 与生成词条均未使用 Markdown 脚注，因此新增语义不会覆盖旧内容。

第一阶段只支持短段落、行内数学和链接。禁止展示公式、表格、代码块、小图和主论证步骤进入 240px 侧栏。

移动端把旁注放回引用段落之后，并始终保持可见。折叠交互不进入第一阶段。

先在一篇数学词条和一篇模型词条试点。每篇建议控制在 3 至 6 条，每条约 120 个汉字；超过建议值产生 lint 警告，不阻止同步。正文移除全部旁注后仍必须逻辑完整。

## 暗色 SVG 方案

### 方案 A：SVG 内部语义颜色与媒体查询

每个 SVG 内定义小型语义颜色表，例如纸张、正文墨线、次要墨线、轴线、辅助线、强调色和两类填充色。默认值为浅色；`@media (prefers-color-scheme: dark)` 覆盖为暗色。

优点：保留单文件、外链 `<img>`、缓存和现有同步架构；手动主题能够通过 `color-scheme` 传播；颜色角色可审查。

风险：279 个存量 SVG 需要迁移；359 个原始颜色中存在少量一次性颜色，不能只做盲目字符串替换。

### 方案 B：同步时生成 `*.dark.svg`

源 SVG 继续只写浅色，构建阶段按颜色映射生成暗色副本；页面根据主题选择资源。

优点：源文件改动较少；生成规则集中。

风险：产物翻倍；手动主题切换需要资源重选；颜色映射无法理解同色在不同图中的语义；调试和缓存更复杂。

### 方案 C：页面统一使用 CSS `filter`

暗色主题下对整个 SVG 做反相、亮度或色相调整。

优点：改动最小，可作为临时诊断手段。

风险：强调色、概率热图、正负颜色和半透明填充同时失真；无法分别控制文字、轴线和背景。

不推荐作为发布方案。

### 方案 D：把 SVG 内联到 HTML

管线读取 SVG 并直接插入页面，使图形可以使用页面 CSS 变量。

优点：主题变量完全统一；可进一步做交互。

风险：HTML 体积增加；多个 SVG 的 `id`、`defs` 和引用可能冲突；扩大 sanitize 与安全边界；偏离当前简单资产模型。

不推荐用于本次目标。

### 暗色 SVG 推荐

采用方案 A。先建立语义颜色契约，再分两类迁移：

1. 批量迁移高频、角色明确的纸墨颜色。
2. 对热图、渐变、正负类别和专用配色逐图复核。

浅色背景矩形优先改为主题纸色或透明。必要图形在两种主题下相对背景至少达到 3:1；图内普通文字至少达到 4.5:1。同步或测试阶段增加静态闸，拒绝新 SVG 引入未登记的纸墨颜色，并抽取代表页做明暗截图回归。

## 推荐顺序

1. 先修暗色 SVG。它是现有内容在已发布主题下的可读性缺陷，并且技术路径已经由规范和本地实验验证。
2. 再引入旁注。先定义作者语法、内容边界和移动端行为，再改同步管线与两篇试点词条。
3. 最后评估把小图或图注移入侧栏。该能力依赖前两项稳定，第一阶段不纳入。

## 已确认的范围

- 暗色 SVG 与 Tufte 旁注分别形成独立需求计划，暗色 SVG 优先。
- 暗色 SVG 使用单文件内部语义颜色、分批迁移和分层视觉验收。
- 旁注同时支持编号旁注与无编号边注；移动端始终可见。
- vault 中的编号旁注使用脚注，无编号边注使用 `marginnote` callout。
- 第一版旁注只允许短文、链接与行内数学，并使用非阻塞密度 lint。
